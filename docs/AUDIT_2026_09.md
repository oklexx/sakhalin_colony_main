## 8. Три режима minimap — отличия и корректность

| режим | что видит агент | сеть | obs источник | когда лучше |
|---|---|---|---|---|
| `flat` | 246-float вектор (деньги/люди/ресурсы/здания/балансы/налоги…) | `ActorCritic` MLP `net_arch` | `cpp.venv.minimap_batch()` не вызывается | быстрый бейзлайн, отладка |
| `minimap` | тензор `(8, 2R+1, 2R+1)` (суша/вода/лес/уголь/железо/нефть/золото/занято) | `ActorCriticCNN` 32@4s2→64@2s2→proj | только миникарта | когда важна пространственность размещения |
| `hybrid` | оба: flat 246 + миникарта | `ActorCriticHybrid` `flat_proj(hidden0) + cnn_proj(cnn(minimap)) → trunk` | оба | лучшее качество при достаточных данных |

**Корректность гибрида** (`python/actor_critic_hybrid.py:88`):
```python
cnn_feat = self.cnn_proj(self.cnn(minimap).flatten(1))
flat_feat = self.flat_proj(flat_obs)
feat = torch.cat([flat_feat, cnn_feat], dim=1)  # → trunk
```
`flat_proj` = `hidden[0]`, CNN = 2 свёртки + proj → trunk `hidden[1:]`. `env_manager` пробрасывает `(flat, minimap)` в `ppo.collect_step`. `rollout_buffer` поддерживает N-D obs (SB3 VecNormalize порядок соблюдён).

**Рекомендация**: для продакшена — `hybrid R=14` (≈29×29). Для быстрых экспериментов — `flat`. Чистый `minimap` без flat теряет экономические сигналы → хуже.

## 9. Почему модель «покупает еду» — разбор + фикс

**Игровая правда:** еда — товар на продажу (как лес/уголь), «жители не едят». `consume` еды нет ни у одного здания (кроме обмена), покупать её смысла нет, кроме как слив денег.

**Старый луп до фиксов:**
- `buy_food_penalty = -3` но `food_need_bonus = 2.0` за постройку Farm при `food<200` давал `~2*log1p((200-food)/10)` до ≈+4, + `build_bonus` + `loan_penalty` слабый → нетто покупка еды + ферма выглядели выгодно в коротком горизонте.
- При `inventory food<200` агент получал бонус за фермы, но также видел, что `MGR:buy_food` берёт `400-food` единиц и даёт `-3` (разово) — дешевле, чем строить ферму за 1000+ и ждать сезонов → локальный оптимум «докупить».
- Штраф за idle (`-2` за 7 дней без строек) толкал к любому действию, включая покупку.
- `res_balance` показывал сурплюс еды (фермы произвели) → агент считал пищевой цикл «полезным».

**Фиксы (частично до этого патча, частично сейчас):**
- `food_need_bonus 2.0→0.8` (и `water_need_bonus`) — теперь ≤ штрафа за покупку.
- `buy_food_penalty 3.0` остаётся чистым штрафом; логика `MGR:buy_food` даёт ещё `-2` если `need==0` (две списания).
- `first_extraction_bonus/extraction_daily` с весом `min(1, 0.25*n_consumers)` → `food/gold weight=0` (никто не потребляет) → фермы не дают добычных бонусов.
- `debt_coeff 0.02→0.1` + `loan_penalty 0.5` ломают кредитный луп, которым финансировалась покупка.
- Добавлен `res_balance` дефицит-бонус (§6): строить производителя имеет смысл только под реальные нужды, а не под склад.

**Остаточный риск:** если оставить `curriculum_resources` с едой — агент снова увидит её в бонусах. Рекомендуется в курикулуме **не отмечать еду** (или оставлять `curriculum_resources=""` но вес всё равно 0). После фиксов BUY_FOOD должен выпасть из топ-действий (проверить барами на «Мониторинге»).
