# Как обучить агента через игру

Эта инструкция — для текущей версии проекта. В проекте есть два разных сценария, и их важно не смешивать:

1. **Обучение на своей игре**: вы играете в окне, программа записывает ваши решения в JSONL, затем агент сначала копирует ваш стиль (BC), а потом доучивается PPO.
2. **Обычное обучение агента**: агент сам играет в симуляции без окна. Для проблемы с водой это сейчас рекомендуемый путь — через пресет **«Этап 1 · База и ресурсы»**, а затем отдельное дообучение на полной экономике.

Запись человеческой игры не превращает клик по конкретной клетке в координатное действие агента. В текущем RL-пространстве записывается решение высокого уровня: «строить Road», «строить WaterChannel», «прожить день», «продать излишки» и т. п.; конкретный участок выбирает та же среда `env.step()`, что и у PPO.

---

## 1. Подготовка один раз

Откройте **Developer Command Prompt for Visual Studio** и перейдите в корень репозитория:

```bat
cd /d C:\путь\к\sakhalin_colony_main
```

Установите Python-зависимости:

```bat
python -m pip install -r requirements.txt
```

После изменений C++ обязательно пересоберите оба компонента. Старый `colony_cpp.pyd` или старый `sakhalin_colony_gui.exe` могут запускаться, но играть по старым правилам — это частая причина ощущения, что исправление «не работает»:

```bat
build_pyext.bat
build_gui.bat
```

Проверьте расширение среды:

```bat
python -c "import sys; sys.path.insert(0, 'python'); import colony_cpp; print(colony_cpp.extension_info())"
```

В выводе не должно быть ошибки про устаревший бинарник. Если менялись `src/`, `include/` или `configs/bases.json`, не пропускайте пересборку.

## 2. Рекомендуемый путь: сначала вода, потом вся игра

Не начинайте с 32 зданий. В полной игре модель видит много легальных действий, а дорога даёт быстрый локальный сигнал; это позволяет ей зациклиться на дорогах и никогда не довести цепочку до водоканала. Сначала нужен маленький навык:

> дорога к воде → водоканал → еда → продажа излишков.

### Вариант A — через UI

1. Запустите:

   ```bat
   python run_train_ui2.py
   ```

2. Перейдите на новую вкладку **«Игра → BC»**.
3. В блоке **«Записать игру или подключить существующие JSONL»** выберите папку
   игр и свежий `sakhalin_colony_gui.exe`. Оставьте сценарий
   **`stage1 · вода сначала`** и нажмите **«Записать игру»**.
4. Сыграйте партию: Road → WaterChannel → дождаться достройки → Farm/Garden.
   Закройте окно игры после партии. Повторите запись с несколькими seed.
5. Если JSONL уже были записаны раньше, нажмите **«Добавить файлы…»** или
   просто укажите папку с ними. Кнопка **«Обновить список»** покажет число
   переходов, эпизодов, размер obs/action и ошибки повреждённых файлов.
6. В нижнем блоке выберите имя BC-модели и нажмите **«Обучить BC»**. Лог
   появится в общей панели UI. После успешного завершения станет доступна кнопка
   **«BC → PPO stage1»** — она запускает обычный PPO от `model.pt` на том же
   water-first сценарии.
7. Когда stage1 устойчиво доходит до воды, откройте вкладку **«Модели»** и
   нажмите **«Дообучить»**: это переведёт модель на полную экономику с меньшим LR.

Если вместо записи своей игры нужно сразу обучать агента самостоятельно,
используйте вкладку **«Курикулум»** → **«Этап 1 · База и ресурсы»**, затем вкладку
**«Обучение»** и кнопку **«Старт»**.

В мониторе для водоканала важны две величины:
   - **доля действия** — как часто модель выбирала WaterChannel;
   - **легальность** — была ли постройка вообще возможна.

Если WaterChannel всё время нелегален, проблема не в «желании» модели: до воды не дошла дорога, не хватает денег или нет подходящей клетки. Если WaterChannel легален, но доля выбора равна нулю, тогда проблема уже в политике/обучении.

### Вариант B — через командную строку

Минимальный прогон этапа 1:

```bat
python train.py --preset stage1 --steps 1000000 --envs 8 --device cuda --name water_stage1
```

Для CPU уменьшите параллелизм:

```bat
python train.py --preset stage1 --steps 200000 --envs 2 --device cpu --name water_stage1_smoke
```

После успешного этапа 1 запускайте **новый** прогон полной игры с дообучением от лучшего чекпойнта:

```bat
python train.py --steps 5000000 --envs 8 --device cuda ^
  --name economy_stage2 ^
  --resume-model %USERPROFILE%\colony_runs\models\water_stage1\best_model.pt ^
  --resume-lr 3e-5
```

В PowerShell перенос строки делается обратным апострофом `` ` ``, либо команду можно написать одной строкой. Для UI это то же самое: вкладка **«Модели»** → выбрать модель `water_stage1` → **«Дообучить»**.

### Как посмотреть результат

```bat
python watch_champion.py --model-dir %USERPROFILE%\colony_runs\models\water_stage1 --visual --seed 42
```

Для диагностики без окна:

```bat
python watch_champion.py --model-dir %USERPROFILE%\colony_runs\models\water_stage1 ^
  --seed 42 --speed 0 --step-log water_stage1_step.log
```

Сначала проверьте именно модель этапа 1. Не подавайте ей вручную полную карту зданий: наблюдение должно восстановить правила из `meta.json`/`best_model.meta.json`.

## 3. Обучение на вашей игре: запись демонстрации

### 3.1 Запуск записи

Создайте каталог для демонстраций и запустите нативное игровое окно:

```bat
mkdir demos
sakhalin_colony_gui.exe --record-demo demos\human_01.jsonl --seed 42 --map-size 280 --curriculum "{\"all_builds\":false,\"allowed_builds\":[\"Road\",\"WaterChannel\",\"Garden\",\"Farm\",\"Mushroom\",\"Fish\",\"SmallHouse\",\"House\"],\"all_resources\":false,\"resource_weights\":[0,1,0,0,0,0,1,1,0],\"stage\":0,\"obs_version\":2,\"enabled_mechanics\":[\"sell\",\"credit\"],\"water_bootstrap\":true}"
```

В репозитории есть тот же сценарий в `configs/curriculum_stage1.json`. В PowerShell длинную строку можно передать так:

```powershell
$curr = Get-Content .\configs\curriculum_stage1.json -Raw
.\sakhalin_colony_gui.exe --record-demo .\demos\human_01.jsonl --seed 42 --map-size 280 --curriculum $curr
```

Если командная строка Windows плохо обрабатывает длинный JSON, используйте этот PowerShell-вариант или запустите запись без ручного курикулума. Для первой записи важнее закончить несколько партий без ошибок; затем BC можно доучить PPO на том же сценарии.

`--record-demo` включает специальный режим:

- каждый записанный шаг проходит через настоящий `env.step()`;
- один шаг агента обычно равен одному игровому дню;
- клики **День**, **Неделя**, строительство, ремонт, снос и консервация записываются;
- Undo, рынок и банк с произвольной суммой в этом режиме заблокированы, потому что у PPO нет соответствующего действия;
- конкретная клетка из клика не сохраняется: сохраняется тип решения, а клетку подбирает RL-среда;
- запись можно закончить закрытием окна. Последние строки без `terminated: true` всё равно пригодны для обучения.

На практике во время записи держите план простым:

1. не спамьте зданиями;
2. сначала доведите Road до открытия WaterChannel;
3. постройте WaterChannel;
4. подождите, пока он достроится;
5. затем стройте одно-два здания, которые используют воду, и продавайте излишки.

Файл `demos\human_01.jsonl` должен расти во время игры. Одна строка — один переход с полями `obs`, `action`, `action_mask`, `reward`, `terminated`.

### 3.2 Проверка записи перед обучением

JSONL — это много JSON-объектов по одному на строку, поэтому проверяйте его целиком так:

```bat
python -c "import json; p='demos\\human_01.jsonl'; rows=[json.loads(x) for x in open(p, encoding='utf-8') if x.strip()]; print('steps=',len(rows),'obs=',len(rows[0]['obs']),'actions=',len(rows[0]['action_mask']),'episodes=',sum(bool(x['terminated']) for x in rows))"
```

Нужно собрать несколько партий, а не обучаться на одной короткой записи. Хорошая стартовая цель — **5–20 партий** и хотя бы несколько тысяч решений суммарно. Записи должны быть сделаны с одной и той же версией `obs_version` и одним и тем же количеством действий.

### 3.3 Behavioral cloning (BC)

BC обучает политику повторять решения из JSONL:

```bat
python -m rl.bc_pretrain ^
  --demo demos\human_01.jsonl demos\human_02.jsonl ^
  --out %USERPROFILE%\colony_runs\models\human_bc\model.pt ^
  --epochs 30 --batch-size 256 --patience 8
```

Можно передать весь каталог:

```bat
python -m rl.bc_pretrain --demo demos --out models\human_bc\model.pt --epochs 30
```

Команда создаст:

- `model.pt` — чекпойнт, совместимый с PPO;
- `model.norm.json` и `normalization.json` — нормализация наблюдений.

Если BC сообщает `obs_size` или `n_actions` mismatch, не смешивайте записи от разных сборок игры.

### 3.4 Проверка BC и дообучение PPO

Сначала посмотрите, что BC-чекпойнт вообще загружается:

```bat
python watch_champion.py --model-dir %USERPROFILE%\colony_runs\models\human_bc --model-file model.pt --seed 42
```

Затем дообучите его в том же сценарии:

```bat
python train.py --name human_bc_ppo --preset stage1 --steps 2000000 ^
  --envs 8 --device cuda ^
  --resume-model %USERPROFILE%\colony_runs\models\human_bc\model.pt ^
  --resume-lr 1e-4
```

Важно: BC из записи с полным набором зданий нельзя бездумно продолжать на `stage1`, если ширина/маска сценария расходятся. Записывайте демонстрацию сразу под тем же пресетом, в котором планируете PPO.

## 4. Что делать, если воды снова нет

Проверяйте по порядку:

1. **Сборка**: после исходников выполнены `build_pyext.bat` и `build_gui.bat`.
2. **Правила модели**: в мета-файле `water_bootstrap`/этап 1, а не 32 здания.
3. **Легальность**: в `step-log` или Мониторинге WaterChannel должен когда-нибудь стать легальным.
4. **Дороги**: дорога не должна занимать сам водный тайл до водоканала; цель — соседняя клетка воды.
5. **Масштаб**: для первого теста используйте фиксированный `--seed 42`, затем проверьте ещё 7, 21, 100 и 777.
6. **Награда**: не сравнивайте только общий return. Смотрите `waterchannel`/`road`/`reached_resources` в `episode_diagnostics.jsonl`.

Признаки неправильного эксперимента:

- запуск `watch_champion.py` с `--curriculum-all` для модели, учившейся на этапе 1;
- дообучение старого чекпойнта после изменения `obs_version`;
- запись человеческой игры через старый exe;
- одна демонстрация из 50 шагов;
- ручное добавление десяти зданий в первую стадию.
