# Двухэтапное обучение: «база и ресурсы» → «вся экономика» (2026-09-21)

Идея: сначала обучить модель минимальной петле выживания (найти воду, построить
водоканал, накормить колонию, продать излишки), затем дообучить её до полной
игры. Реализовано на существующем функционале курикулума; новое — пресет
«Стадия 1», полный гейтинг всех 11 менеджерских слотов и человеческие подписи
в UI.

## Контракт

### Пресет «Стадия 1: база и ресурсы»

Единый источник — `rl/curriculum.py` `STAGE1_PRESET` + `apply_stage1_preset()`.
Применяется из CLI (`train.py --preset stage1`) и из UI (кнопка «Этап 1 · База
и ресурсы» на вкладке «Курикулум»); разъехаться они не могут — регресс
`tests/test_stage1_preset.py::test_stage1_preset_name`.

| Измерение | Значение | Механизм |
|---|---|---|
| Здания (8) | Road, WaterChannel, Garden, Farm, Mushroom, Fish, SmallHouse, House | `unlock_ids` + жёсткий гейт PR 1–2 |
| Приоритетные ресурсы | water, food, wood | `curriculum_resources` (PR 4, веса 1/0) |
| Действия ИИ | только «продать излишки» и «кредит» | `disabled_mechanics` (см. ниже) |
| Критерий eval | 365 дней, 3 здания | `eval_min_days` / `eval_min_bases` |
| Налог | normal, неоплаченный → долг банку | `tax_to_debt=true` (календарь не замирает) |

Обоснование состава — экономика `configs/bases.json` + механика
`Base::end_day` (**здание не производит без входных ресурсов на складе**):

- Sawmill ест нефть+железо, Coalmine — дерево+энергию, а Refinery стоит
  82 684 (весь стартовый бюджет) — «классические» производители в минимальной
  петле мертвы. Поэтому добыча = вода (WaterChannel, входов нет) и еда
  (Mushroom на лесу без входов; Garden/Farm на воде — только после канала).
- Дорога (400) — единственный способ дотянуться до дальней воды
  (`ROAD_E/W/S/N` + целевой `pick_dir_cell`, см. REMAINING_WORK P0-1).
- Дома не дают производственной награды, но оставлены: на этапе 2 «строить
  жильё, когда денег много» не должно быть новым поведением.
- Кредит оставлен: единственный способ профинансировать дорогу+канал при
  съеденном бюджете; кредитный луп по-прежнему ломают `loan_penalty` +
  `debt_coeff`.
- `w_food` в PR 4 был 0 («нет зданий-потребителей еды») — здесь еда в приоритете
  сознательно: `Mushroom`/`Fish` дают первую продажу со склада.

### Гейтинг механик: 11 слотов через 8 механик

Раньше гейтинг покрывал 5 из 11 менеджерских слотов (improve_land,
preserve/unpreserve, take/repay loan). Теперь — все:

| Механика (имя в транспорте) | Слоты менеджеров |
|---|---|
| `improve_land` | 0 IMPROVE_LAND |
| `repair` | 1 REPAIR, 2 RESTORE_ALL |
| `destroy` | 3 DESTROY |
| `preservation` | 4 PRESERVE, 5 UNPRESERVE |
| `sell` | 6 SELL |
| `buy_food` | 7 BUY_FOOD |
| `credit` | 8 TAKE_LOAN, 9 REPAY_LOAN |
| `manual_tax` | 10 PAY_TAX |

Таблицы живут в `include/colony/constants.h` (`MECHANIC_NAMES`,
`MANAGER_MECHANIC`, `mechanic_index`) — их обязана зеркалить
`rl/curriculum.py` `MECHANIC_NAMES` (порядок = индекс; регресс
`test_mechanic_tables_in_sync` читает заголовок C++ регуляркой). Порядок первых
трёх имён менять нельзя: **легаси-мета старых прогонов содержит только
`improve_land`/`preservation`/`credit`** — они остаются валидными именами и
парсятся в свои механики (`stage1_gate_check` §6).

Поведение `step()` в закрытый слот не изменилось (PR MECHANIC_CURRICULUM):
чистый `error_penalty`, календарь/деньги/кредит не трогаются.

### Дефолты

- **Новый прогон** (`Config()` без полей гейтинга): минимальный режим —
  включены `sell` и `credit`, расписание разблокировки пустое. Это же —
  дефолт UI после применения пресета.
- **Старый конфиг без полей** (`Config.from_dict` без `disabled_mechanics`):
  легаси — все 8 механик (все 11 слотов), как и обучались старые модели.
- **Оценка/наблюдение старых чекпойнтов**: в мете нет механик → все включены
  (`resolve_state`: None → полный набор).

## Этап 2 — как запускать

Рекомендованный путь — отдельный прогон с весами этапа 1:

```
# UI: вкладка «Модели» → выбрать модель этапа 1 → «Дообучить».
#    Кнопка сама включает полное пространство зданий/ресурсов/действий,
#    ставит LR=0.00003 и пороги проверки 730 дней / 5 зданий.
# CLI:
python train.py --steps 5000000 --resume-model ~/colony_runs/models/s1_run/best_model.pt \
    --resume-lr 3e-5            # либо передать желаемую скорость через --lr
```

При дообучении Adam-моменты из checkpoint сохраняются, но скорость обучения
берётся из новой конфигурации (`--resume-lr`, иначе `--lr` в CLI; поле LR в UI),
а свежий PPO scheduler и его `base_lrs` используют то же значение. Скорость из
чекпойнта не должна незаметно перезаписать выбор пользователя.

Смена гейтинга внутри живого прогона запрещена для механик (re-lock) —
расписания только аддитивные; этап 2 как отдельный прогон обходит это
ограничение честно: политика доучивается на полное пространство действий,
value-функция перестраивается с тёплого старта.

Почему не «один прогон с расписанием»: `difficulty` фиксируется при создании
среды, а смена состава наград (ресурсные веса) в середине прогона ломает
сравнимость кривых return. Расписания (`curriculum_schedule`,
`mechanics_unlock_schedule`) остаются доступными для тех, кто хочет gradual.

## Открытые вопросы (вне скоупа)

1. **Метрики этапа 1** — день первой добычи воды/еды, `priority_reached`,
   дороги к воде: в TensorBoard частично есть (`priority_reached`), отдельной
   панелью в UI пока не вынесено.
2. **Light-режим** для этапа 1 (2× деньги, без налога) не включён в пресет:
  `tax_to_debt` уже не даёт эпизоду умереть на 365-й день. Если замер покажет,
  что налог давит обучение — добавить `"difficulty": "light"` в пресет одним
  ключом (но тогда этап 2 обязан стартовать на normal с дообучением).
3. Windows-сборка `bindings.cpp` (pybind11) — проверить `build_pyext.bat`
  перед мержем: в Linux-песочнице pybind11-заголовков нет, правки транспорта
  механик симметричны `env.cpp` и покрыты `curriculum_check`+`stage1_gate_check`
  на уровне ядра, но линковку .pyd надо прогнать на Windows.
