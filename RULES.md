# RULES — правила написания кода (для человека и ИИ)

Краткие, обязательные правила. Конфликт с этим файлом — в пользу этого файла;
если правило устарело — правь его в этом же файле одним коммитом.

## Стек (не менять без причины)

- Ядро симуляции: **C++17**, pybind11 → `python/colony_cpp.pyd` (CMake ≥ 3.20).
- Обучение: **Python 3.10+**, PyTorch (GPU), NumPy, Gymnasium-совместимые
  обёртки, PySide6 (UI `train_ui2/`).
- **Не вводить новые сторонние зависимости** без явного решения. Математика —
  stdlib/NumPy/PyTorch; «лёгкий» формат данных — только JSON (configs/).
  pandas/scipy не используются и не добавляются.

## Python

- Аннотации типов — **обязательны** во всех публичных функциях и методах
  (включая параметры и возвращаемый тип). `from __future__ import annotations`
  в начале модуля.
- Конфигурация — dataclass (`rl/config.py`); новые параметры — только через
  `Config`/`RewardConfig`, без глобальных констант и магов-чисел.
- Идентификаторы — английский; **комментарии и docstrings — русский** (рабочий
  язык проекта), объяснять «зачем», а не «что».
- Пути — `pathlib.Path`, не строковые конкатенации.
- Тихо не глотать: `except Exception: pass` запрещён без комментария с причиной.

## C++

- Стандарт C++17, без новых внешних зависимостей (только `include/third_party/`).
- Namespace `colony`; константы игры — в `include/colony/constants.h`, не
  хардкодом по файлам.
- Награды вычисляются в `src/rewards.cpp`/`src/env.cpp` по `RewardConfig` —
  новые веса только через `RewardConfig`, новые магические числа в формулах —
  только с константой/флагом.

## Золотое правило синхронизации (самая частая причина багов)

1. **Веса наград** синхронно живут в трёх местах и должны совпадать:
   `configs/reward_v4.json` (канон, побеждает) ↔ `rl/config.py`
   (`RewardConfig`, дефолты) ↔ `include/colony/env.h` (C++ `RewardConfig`).
   Правка в одном месте без остальных = баг (история: B1, N3–N5).
2. **Curriculum** — единый источник `rl/curriculum.py`
   (`build_state` → `CurriculumState`). Python вычисляет разрешённый набор,
   C++ только применяет. Не дублировать логику в eval/watch/обучении.
3. **Порядок `configs/bases.json` = индекс действия BUILD_***. Не переставлять
   записи; добавлять здание в конец и синхронно обновлять `obs_size()`,
   тесты и список действий в README.
4. **Наблюдение**: изменение размера/состава obs → обязательно новая
   `obs_version` (`CURRENT_OBS_VERSION` в `rl/curriculum.py`) + обновление
   тестов (`test_watch_obs_version.py`) и README §5.2. Старые версии должны
   оставаться строгими префиксами.
5. **45 действий (49 слотов)**: маски (`action_mask`, `mask_managers_by_*`)
   синхронны между C++ и Python; изменение состава действий — только с тестом.

## Тесты (TDD-lite)

- **Сначала тест, потом правка**: баг воспроизводится упавшим тестом
  (`python -m pytest tests/test_x.py -x`), потом фикс, тест зелёный.
- Python-тесты — `tests/test_*.py` (pytest). C++-регрессии и зонды наград —
  `tests/cpp/*.cpp`, сборка без pybind11:
  `g++ -std=c++17 -O1 -Iinclude -Iinclude/third_party -o /tmp/check …`
- Перед коммитом: `make test` (или `python -m pytest`) — не ломать зелёные
  тесты; если тест устарел по смыслу — править тест в том же коммите с
  комментарием.
- Тесты, требующие `colony_cpp.pyd`, должны дегра gracefully: скипаться
  через `colony_cpp_api.require_colony()`, а не падать с ImportError.

## Артефакты и git

- **Никогда не коммитить**: `*.pyd`, `*.so`, `*.exe`, `*.pt`, `*.onnx`, логи —
  см. `.gitignore`. Протухший бинарь в git затеняет исправленные исходники
  (см. `python/colony_cpp_api.py`).
- Чекпойнты и логи обучения — `~/colony_runs/` (вне репозитория).
- Сообщения коммитов — по существу (что и зачем), без «fix», «wip».

## Стиль общения в логах и ошибках

- Ошибки — с контекстом: номер шага, индекс env, id действия, ожидаемое
  состояние (пример: «obs mismatch: checkpoint v1 (289) vs env v2 (299)»).
- Отладочный вывод — только за флагом/параметром, не на stdout постоянно.
